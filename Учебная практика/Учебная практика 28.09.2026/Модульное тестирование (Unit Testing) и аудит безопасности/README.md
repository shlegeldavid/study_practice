# Модульное тестирование и аудит безопасности

Самостоятельная версия приложения на Python, Tkinter и SQLite. Все нужные
файлы находятся в этой папке. Сохранены список и карточка партнера,
история продаж и калькулятор материалов из предыдущего задания.

## Запуск

Нужен Python 3.10+ с Tkinter. Дополнительные библиотеки не требуются.
Из этой папки выполните:

```text
python app.py
```

При первом запуске создается `partners.db` с демонстрационными данными.
Чтобы продолжить со старой базой, до первого запуска скопируйте ее сюда.
Партнеры и продажи сохраняются; исходная база прошлого задания не меняется.
Не заменяйте уже созданную здесь базу, если в ней есть нужные записи.

На главной форме «Расчет материалов» открывает калькулятор. Выберите тип
продукции и материала, введите количество и оба положительных параметра,
нажмите «Рассчитать». Результат выводится в форме. Демонстрационный пример:
типы 1 и 1, количество 100, параметры 2.5 и 3.0 дают расход 945.
Коэффициенты и проценты в справочниках являются учебными значениями.

## Пять обязательных тест-кейсов

Отдельный модуль `test_material_calculation.py` использует `unittest`.
Каждый тест работает с собственной базой SQLite в памяти.

| Случай | Название теста | Ожидаемый результат |
| --- | --- | --- |
| Стандартный расчет | `test_standard_calculation` | 945 |
| Округление вверх | `test_rounding_up` | 1.26 округляется до 2 |
| Несуществующий тип | `test_nonexistent_or_invalid_type_returns_minus_one` | -1 для неверного ID продукции или материала |
| Отрицательные параметры | `test_negative_parameters_return_minus_one` | -1 для отрицательного первого или второго параметра |
| Нулевое и отрицательное количество | `test_zero_and_negative_quantity_return_minus_one` | -1 для количества 0, -1 и -100 |

Дополнительно проверяются `NaN`, бесконечность, неверные типы значений,
точность дробного расчета, границы процента брака, чтение актуальных
справочников и отсутствие изменений базы при вычислении.

## Запуск проверок

Только тесты математического метода:

```text
python -m unittest discover -s . -p "test_material_calculation.py" -v
```

Все проверки, включая SQL, журналирование и настоящие виджеты Tkinter:

```text
python -m unittest discover -s . -p "test_*.py" -v
```

Комплексный набор содержит 56 тестов. GUI-тестам требуется рабочий Tkinter.
Проверки используют временные базы и журналы; изменять рабочие данные
приложения для тестов не требуется. Сообщения в GUI-тестах перехватываются,
чтобы не требовать ручного закрытия диалогов.

## Защита SQL

В `test_sql_security.py` проверяются добавление, изменение и чтение с
SQL-подобными строками, а также фиксированный текст запросов в рабочих модулях.
В GUI-тестах проверяется сохранение такой строки через форму партнера.

Пользовательские значения передаются отдельно от текста SQL через `?` или
именованные параметры `:name`, `:partner_id` и другие. Кавычки не экранируются
вручную и не вставляются в текст запроса. Поиск и авторизация в приложении
не реализованы. Результаты проверки описаны в `SECURITY_AUDIT.md`.

## Журнал ошибок

При запуске приложение настраивает стандартный модуль `logging` через
`app_logging.py`. Файл `app.log` создается рядом с `app.py`, независимо
от текущей рабочей папки. Новые записи дописываются, а не заменяют старые.
Кодировка — UTF-8. Формат записи:

```text
ГГГГ-ММ-ДД ЧЧ:ММ:СС | ERROR | Ошибка базы данных при попытке загрузить партнеров: ...
ГГГГ-ММ-ДД ЧЧ:ММ:СС | WARNING | Ошибка ввода в карточке партнера: ...
```

Дата и время берутся из часов компьютера. Записываются перехваченные ошибки
SQLite, ошибки ввода партнера, ошибки расчета, возврат `-1` и отсутствие
выбранного партнера в базе. Промежуточная ошибка преобразования рейтинга
объясняется пользователю и записывается при обработке ошибки в форме,
без дублирования одной ошибки в нескольких местах.

Имена, телефоны, адреса, email и содержимое числовых полей не записываются
в журнал. Вместо них сохраняются контекст операции и текст ошибки.
Если файл нельзя открыть, приложение явно сообщает об этом в консоли
и записывает туда ошибки с тем же форматом даты и времени.

Локальные `partners.db` и `app.log` исключены из Git правилами игнорирования.
