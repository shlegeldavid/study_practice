# Аудит SQL и обработки ввода

Дата проверки: 03.10.2026.
Область: самостоятельная SQLite-версия приложения в этой папке.

## Проверенные пути

| Путь | Передача данных в SQL | Результат |
| --- | --- | --- |
| Добавление партнера из `PartnerEditWindow` | Именованные параметры `:type`, `:name`, `:rating`, `:address`, `:director`, `:phone`, `:email` | SQL-подобный текст сохраняется как значение поля |
| Изменение партнера | Именованные параметры полей и `:partner_id` | Изменяется только выбранная запись |
| Чтение партнера по ID | `WHERE id = ?`, отдельный кортеж аргументов | Строка `1 OR 1=1` не выбирает другие записи |
| История продаж | `WHERE s.partner_id = ?` | SQL-подобный ID возвращает пустую историю |
| Расчет материалов | Два `?` для ID типов; предварительная проверка целочисленных ID | Неверные ID возвращают -1 |
| Список партнеров и списки типов | Фиксированные запросы без пользовательских значений | Динамическая подстановка ввода отсутствует |
| Создание и обновление схемы | Статические SQL-строки и константы | Пользовательский ввод в SQL схемы не попадает |
| Поиск и авторизация | Не реализованы | Не применимо |

Текст SQL не строится конкатенацией, f-строками или форматированием значений
пользователя. Значения передаются драйверу SQLite отдельно от запроса.
Само наличие SQL-подобного текста в поле не запрещается: параметризация
позволяет хранить его буквально без выполнения как команды.

## Фактически выполненные проверки

- Добавление SQL-подобных значений в текстовые поля партнера: значения
  сохранены буквально, таблицы и четыре демонстрационные продажи остались.
- Изменение партнера строкой с `DROP TABLE`: другой партнер не изменился,
  связи продаж сохранились; `PRAGMA foreign_key_check` не выявил нарушений.
- Чтение, изменение и история с ID `1 OR 1=1`, `1; DROP TABLE partners; --`
  и `' OR '1'='1`: записи не раскрыты и не изменены.
- Сохранение SQL-подобного наименования через настоящую форму партнера:
  появился один новый партнер, таблица осталась доступной.
- Статическая проверка SQL-вызовов в `app.py`, `partner_database.py`,
  `material_calculation.py` и `example_material_calculation.py`:
  текст запросов фиксирован, значения связываются параметрами.
- Нулевое и отрицательное количество, отрицательные размеры, пустые поля,
  `NaN`, бесконечность, неизвестный или удаленный тип: показана ошибка,
  интерфейс остается работоспособным; -1 не выводится как расход материала.
- Ошибки SQLite и ввода записываются с датой и временем. Тест карточки
  подтверждает, что название и email партнера в журнал не попадают.

Полный набор: **56 тестов прошли**, включая математический метод,
безопасность SQL, журналирование, GUI и сохраненные функции приложения.
По проверенным путям уязвимых подстановок пользовательского ввода в SQL
не обнаружено. Отчет касается указанных локальных путей; сетевых интерфейсов
и внешней системы авторизации в этой версии нет.
