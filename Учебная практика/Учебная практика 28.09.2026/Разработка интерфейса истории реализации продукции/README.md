# История реализации продукции

Самостоятельное приложение на Python, Tkinter и SQLite. Продолжает предыдущие
задания: список партнеров, расчет скидки, добавление и редактирование,
проверка ввода и уведомления. Все файлы для запуска находятся в этой папке.

## Запуск

Нужен Python 3.10+ с Tkinter. Дополнительные библиотеки не требуются.
Из этой папки выполните:

```text
python app.py
```

При первом запуске создается локальный `partners.db` с четырьмя партнерами,
тремя видами продукции и четырьмя продажами. Партнер «Север» не имеет продаж.

## Просмотр истории

1. Выберите партнера переключателем рядом с названием или нажатием на карточку.
   При необходимости прокрутите список колесом мыши или полосой справа.
2. Нажмите «История продаж». До выбора партнера кнопка недоступна.
3. Откроется `PartnerHistoryWindow`, которому передается `partner_id`.
   Заголовок содержит название выбранного партнера:
   «CRM: История реализации продукции — ООО «Ромашка»».
4. Таблица показывает наименование продукции, количество в штуках и дату
   продажи в формате `ДД.ММ.ГГГГ`. Новые продажи идут первыми.
5. Под таблицей указаны число отгрузок и общий объем. Если продаж нет,
   появляется сообщение «У партнера пока нет продаж».
6. «Назад» или крестик закрывают историю и возвращают к выбранному партнеру.

Окно использует оформление предыдущих заданий: шрифт Arial, фон `#f3f3f3`,
белые карточки и таблицу, шапку `#e8f1e9`, зеленые кнопки `#3f7f56`.
Логотип и иконка находятся в `resources`. У таблицы есть вертикальная
и горизонтальная прокрутка.

## Запрос и совместимость базы

В `partner_database.py` история получается параметризованным SQL-запросом:

```sql
SELECT
    COALESCE(p.name, 'Не указано') AS product_name,
    s.quantity,
    CASE
        WHEN s.sale_date IS NULL OR TRIM(s.sale_date) = '' THEN 'Не указана'
        ELSE COALESCE(STRFTIME('%d.%m.%Y', s.sale_date), s.sale_date)
    END AS sale_date
FROM sales_history AS s
LEFT JOIN products AS p ON p.id = s.product_id
WHERE s.partner_id = ?
ORDER BY s.sale_date DESC, s.id DESC;
```

`?` получает ID выбранного партнера отдельно от текста запроса. Продукция
хранится в `products`, продажи связаны с ней через `sales_history.product_id`.
Внешние ключи включены для каждого подключения.

Чтобы продолжить со старой базой, до первого запуска скопируйте ее
`partners.db` в эту папку. Не заменяйте уже созданную здесь базу с нужными
записями. Программа добавит недостающие поля и справочник продукции в копию,
сохранив партнеров, ID продаж, даты, объемы и скидки.

В прошлых заданиях продажи не содержали названия продукции. Для таких строк
показывается «Не указано», а при отсутствии даты — «Не указана». `LEFT JOIN`
сохраняет эти строки в истории. Названия для старых продаж не подставляются
из демонстрационных данных; их можно связать с продукцией по достоверным
данным в базе. Неизвестный формат старой даты выводится как хранится.

## Проверка

```text
python -m unittest discover -s . -p "test_*.py" -v
```

Тесты проверяют выборку истории отдельного партнера, названия продукции,
формат дат, порядок продаж, пустую историю, параметризацию и внешние ключи.
Также проверяются сохранность старой базы, CRUD и валидация карточки.
