# Интеграция расчета материалов и комплексное тестирование

Самостоятельное приложение на Python, Tkinter и SQLite. В этой папке находятся
все файлы для запуска. Сохранены список партнеров, добавление и редактирование,
расчет скидки, история реализации продукции и ядро расчета материалов.

## Запуск

Нужен Python 3.10+ с Tkinter. Дополнительные библиотеки не требуются.
Из этой папки выполните:

```text
python app.py
```

При первом запуске создается `partners.db` с демонстрационными партнерами,
продажами и справочниками типов продукции и материалов. Для продолжения
со старой базой до первого запуска скопируйте ее `partners.db` в эту папку.
Исходная база не меняется; существующие партнеры и продажи сохраняются.
Не заменяйте базу этой папки, если в ней уже есть нужные данные.

## Калькулятор

1. На главной форме нажмите «Расчет материалов».
2. В `MaterialCalculatorWindow` выберите тип продукции и тип материала.
   Списки загружаются из базы и показывают ID и название. Произвольный
   несуществующий тип ввести нельзя.
3. Введите количество продукции и оба параметра изделия.
   Количество должно быть целым числом больше 0. Оба параметра должны
   быть положительными конечными числами. Допускаются `2.5` и `2,5`.
4. Нажмите «Рассчитать». Результат появится прямо в форме.
5. После изменения исходных данных прежний результат сбрасывается.
6. «Назад» или крестик закрывают калькулятор и возвращают к списку партнеров.

Калькулятор использует цвета, шрифт Arial, логотип и иконку предыдущих заданий.
Он работает отдельно от карточки партнера и не изменяет записи продаж.

## Формула и пример

Вызывается метод `MaterialCalculator.calculate_material_amount` с пятью
параметрами: `product_type_id`, `material_type_id`, `quantity`, `param_1`, `param_2`.
Коэффициент и процент брака читаются из SQLite при каждом расчете:

```text
ceil(param_1 × param_2 × коэффициент × quantity × (1 + процент_брака / 100))
```

Учебные справочники содержат:

| Тип продукции | ID | Коэффициент |
| --- | ---: | ---: |
| Ламинат | 1 | 1.2 |
| Паркетная доска | 2 | 1.5 |

| Материал | ID | Брак, % |
| --- | ---: | ---: |
| Демонстрационный материал А | 1 | 5 |
| Демонстрационный материал Б | 2 | 2.5 |

Эти значения демонстрационные, поскольку конкретные справочники в условии
не приведены. Заполненные справочники не перезаписываются.

Для продукции 1, материала 1, количества 100 и параметров 2.5 и 3.0:

```text
2.5 × 3 × 1.2 × 100 × 1.05 = 945
Необходимое количество материала: 945
```

## Обработка ошибок

- Пустые поля, текст вместо чисел и дробное количество вызывают сообщение
  с инструкцией исправить ввод. Форма остается открытой.
- Нулевое или отрицательное количество, отрицательные или нулевые параметры,
  `NaN`, бесконечность и отсутствующий тип дают `-1` из метода. Интерфейс
  обрабатывает это значение: сообщает об ошибке и не показывает `-1`
  как количество материала.
- Если выбранный тип удалили из базы после открытия окна, повторный расчет
  сообщает об ошибке. Нужно закрыть калькулятор и открыть его снова.
- Ошибка доступа к базе или SQL обрабатывается отдельным сообщением
  «Ошибка базы данных». Старый результат сбрасывается.
- Если число слишком велико для отображения средствами Python,
  появляется сообщение уменьшить количество или параметры.

После исправления ввода можно повторить расчет в той же форме.

## Комплексная проверка

```text
python -m unittest discover -s . -p "test_*.py" -v
```

Проверяются формула и точность округления, справочники, CRUD, история продаж,
проверка карточки, а также работа настоящих виджетов Tkinter:
нажатие кнопки расчета, вывод результата, неверные значения, возврат `-1`,
удаленный тип, ошибки SQLite, повторный расчет и закрытие окна.
GUI-тестам требуется рабочий Tkinter; они используют отдельные временные базы.
В тестах сообщения перехватываются, чтобы не требовать ручного закрытия диалогов.
Необработанные ошибки обработчиков Tkinter фиксируются как ошибки теста.

В `test_code_style.py` проверяются правило «не более одной команды на строку»
и именование функций, аргументов и переменных в `snake_case`.
Константы используют `UPPER_CASE`, классы сохраняют обычный для Python стиль
`CamelCase`. Служебные методы `setUp` и `tearDown` сохраняют обязательные имена
API `unittest`. Комментарии оставлены для неочевидных причин: точный расчет
дробей, сброс устаревшего результата, привязка ID карточек и совместимость базы.
