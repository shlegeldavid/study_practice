# Ядро алгоритма расчета материалов

Самостоятельная версия приложения на Python, Tkinter и SQLite, продолжение
предыдущего задания с историей реализации продукции. В этой папке находятся
все нужные файлы. Добавлено ядро расчета; интерфейс вызова метода относится
к следующему заданию по интеграции.

## Метод

В `material_calculation.py` класс `MaterialCalculator` получает открытое
соединение с SQLite. Метод `calculate_material_amount` принимает ровно пять
входных параметров:

```python
calculate_material_amount(
    product_type_id: int,
    material_type_id: int,
    quantity: int,
    param_1: float,
    param_2: float,
) -> int
```

Алгоритм соответствует условию задания:

1. Базовый расход на единицу = `param_1 × param_2 × коэффициент продукции`.
2. Чистый расход = `базовый расход × quantity`.
3. Расход с браком = `чистый расход × (1 + процент брака / 100)`.
4. Результат округляется вверх функцией `ceil` после всех вычислений.

Десятичные значения преобразуются в `Fraction` из стандартной библиотеки.
Это исключает лишнюю единицу при округлении из-за двоичной погрешности
`float`, например при вычислении `0.1 × 0.2 × 50`.

Метод возвращает `-1`, если тип не существует, ID имеет неверный формат,
количество не является целым положительным числом либо параметры продукции
не являются положительными конечными числами. Нулевые параметры тоже
недопустимы, поскольку в условии они должны быть положительными.
Значения `NaN`, бесконечность, строки и логические значения отклоняются.

## Справочники

Коэффициент читается из `product_types`, процент брака — из `material_types`.
Внутри метода выполняется параметризованный запрос по двум ID. Расчет только
читает справочники и не изменяет базу. Открытие и закрытие соединения выполняет
вызывающий код, как в предыдущих заданиях.

Процент хранится в шкале от 0 до 100: значение `5` означает **5%**, а не `0.05%`.
Коэффициент должен быть больше нуля. Эти ограничения проверяются в базе и методе.

При подготовке приложения пустые справочники заполняются учебными значениями:

| ID типа продукции | Название | Коэффициент |
| --- | --- | ---: |
| 1 | Ламинат | 1.2 |
| 2 | Паркетная доска | 1.5 |

| ID материала | Название | Брак, % |
| --- | --- | ---: |
| 1 | Демонстрационный материал А | 5 |
| 2 | Демонстрационный материал Б | 2.5 |

Это демонстрационные данные: конкретные коэффициенты и проценты в условии
не приведены. Ранее заполненные справочники не перезаписываются. При расчете
используются актуальные значения из базы, а не встроенные в метод константы.

Старая база обновляется созданием новых таблиц. Данные партнеров и история
продаж сохраняются. Для продолжения работы можно до первого запуска
скопировать `partners.db` прошлого задания в эту папку; исходный файл не меняется.
Не заменяйте уже созданную здесь базу, если в ней есть нужные данные.

Как и остальные методы базы, расчет передает ошибки подключения или SQL
вызывающему коду как `sqlite3.Error`. Они отличаются от неверных входных данных,
для которых результат равен `-1`.

## Запуск

Нужен Python 3.10+ с Tkinter, дополнительные пакеты не требуются.
Из этой папки выполните:

```text
python example_material_calculation.py
```

Пример подготавливает локальную базу и вызывает:

```python
calculator = MaterialCalculator(connection)
result = calculator.calculate_material_amount(1, 1, 100, 2.5, 3.0)
```

Расчет: `2.5 × 3 × 1.2 × 100 × 1.05 = 945`.
Ожидаемый вывод:

```text
Необходимое количество материала: 945
```

Предыдущее приложение со списком партнеров, карточкой и историей запускается
командой `python app.py`.

## Проверка

```text
python -m unittest discover -s . -p "test_*.py" -v
```

Тесты проверяют формулу, окончательное округление, чтение справочников,
некорректные ID, количество и параметры, а также сохранность прежних функций.
